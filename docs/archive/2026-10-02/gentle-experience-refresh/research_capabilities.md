## B. 入口、主流程与可借鉴产品

现有路径是“写下 → 标签/日期 → 保存 → 列表查找 → 点正文再编辑”，低负担日常记录并不需要先建文件夹。下面取成熟做法，不复制全部产品功能。

| 官方参考 | 已核实做法 | 对晴笺的取舍 |
| --- | --- | --- |
| [Memos 核心记录](https://usememos.com/docs/usage/memos) | 全局捕获、本机自动草稿、时间线、重要记录固定；关系通过选择其他记录创建，入/出引用分别显示 | 可借鉴快速捕获与草稿反馈；其编辑方式暴露 Markdown，不符合晴笺所见即所得边界。协作/空间/公开分享无需移植 |
| [Memos 标签](https://usememos.com/docs/usage/tags) | 标签提取/编辑/查询采用一致规则，可组合属性；代码和链接等上下文不生成标签 | 晴笺可先补精确标签+未完成筛选；改变既有标签语法会影响旧内容，不以本轮低风险优化引入层级/emoji语法迁移 |
| [Joplin 搜索](https://joplinapp.org/help/apps/search/) | 有标签、完成状态、日期过滤和快速定位；其FTS4对中文等语言采用自定义搜索以补词边界限制 | 借鉴可见筛选和快捷搜索；不把“加入 SQLite FTS”当作中文查找的免费改进。先量测实际数据量再决定索引 |
| [Obsidian 书签](https://obsidian.md/help/Plugins/Bookmarks) | 常用文件、搜索等可书签化并快速返回 | 晴笺已有固定标签可解决一部分重复访问；笔记收藏或保存组合搜索是新能力，不与标签固定混为一谈 |
| [Obsidian 双向链接](https://obsidian.md/help/plugins/backlinks) | backlinks源于真实内部链接，区分已链接引用和仅名称提及 | 图上的连线必须有数据语义。共标签是相似线索，不自动等于显式关系，更不能让随机装饰连线冒充知识图谱 |
| [Joplin 导入导出](https://joplinapp.org/help/apps/import_export/) | 备份格式保存内容及元数据，单条也可导出其他格式；复杂HTML转纯文本可能损失样式 | 晴笺保留全量JSON作为恢复备份，单条复制可只针对显示内容；不要先引入PDF/任意HTML或多格式迁移系统 |

Memos为自托管产品，离线/服务端模型与晴笺本机应用不同；这里只采用其短记录与操作模式，不能推断技术栈适用。

## C. 既有架构边界与候选成本

观察到的边界：App owns notes/transactions/filter/theme/composer状态；store owns 浏览器序列化/草稿/迁移；desktop 是 Tauri 桥；Rust owns SQLite/凭据/network；NotesView/Ledger/SettingsView/Composer/AiPanel 已以 props 隔离（`App.tsx:19-69,72-133`；`desktop.ts:4-15`）。筛选只是 `useMemo` 内字符串判断，金额/日期/标签存在纯函数。当前没有粒子依赖（package.json:16-32）。

**（推断）** 相对于引入全局状态库、事件总线或通用 repository，沿 props 边界整理组件、把选定的过滤/排序计算作为纯函数、让特效独立持有帧数据，更容易控制本轮风险。粒子位置变化不应导致笔记状态写入或整个App逐帧重新渲染。独立边界用于隔离已经存在的职责，不为假设中的同步/插件提前扩建。实际文件拆分属于后续结构整理阶段，调研不指定patch。

### 新数据能力的比较与暂缓理由（推断）

- **笔记收藏/置顶**：收益是常用清单单击可回访；但若希望跟随备份/桌面数据，需要TS字段、Rust Note serde default、CREATE/ALTER迁移、SELECT/INSERT、备份旧数据默认值与回收站政策。`lib.rs:14,33,44-45,57`逐字段读写会丢掉仅前端新增字段，不能只加localStorage宣称多端一致。最低还需旧SQLite、旧JSON、往返保存测试。标签固定已满足部分收益，可先等需求。
- **单条复制生成新笔记/模板**：复用旅行清单有价值，但容易意外复用done/deletedAt/id/date，需定义复制后的语义；不需要schema，但需稳定行为回归。用户没有提出模板场景，可晚于单条复制。
- **笔记历史**：安全收益高；需要快照/保留规则、表/备份版本、编辑保存触发、恢复与删除政策，增加存储成本。Rust目前零测试时，不宜混在视觉刷新里完成一个未经验证的历史系统。
- **真实关系/双向链接/知识图谱**：新增关联UI、稳定ID引用、删除/恢复后的悬挂关系、备份导入ID冲突、可读纯文本格式或关联表、Rust迁移、索引与图布局，成本高。主题/名称匹配无法替代稳定链接；只绘制“同标签关系”也必须声明推断语义。先区分用户要氛围还是可导航知识网络。

## D. 粒子连线、节点发光与“4d”的边界

“4d”不是本项目已有实体；无法仅凭用户原句判断是四维数学可视化、3D纵深随时间变化还是轻微视差。以下是待确认解释。

1. **装饰节点**：不读取笔记正文，不代表记录数量/联系；少量连线、明暗与近远变化带来纸感边缘的空间气氛。无schema/AI数据。不能点击进入不存在的关联，也不替代内容。
2. **实际知识节点**：每个节点映射笔记ID，连线映射真实链接或明确标注的共标签，点击有阅读/回访行为。它是新的信息导航能力，必须经过关系与删除/导入设计；不是同一装饰任务。
3. **空间纵深（候选理解）**：2D上用大小/明暗/视差表达层次，时间作为变化维度即可产生空间感；这不等于真实4D数学可视化。低频位移仍要可停止，不在编辑正文下漂移。

### 共同约束与可执行性能预算（候选目标，**尚未测量**）

官方 [Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API) 提供visible/hidden变化；[DPR](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio)控制Canvas显示与内部像素尺寸；[W3C C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)支持尊重reduced-motion。仅依赖浏览器后台rAF暂停不足以表达用户开关与组件卸载清理。

| 候选预算 | 测量方法/拒收条件 |
| --- | --- |
| 装饰桌面最多24节点、60条可见线；窄屏最多12节点/24线，目标30fps | DevTools Performance录制30秒和截图计数；24节点两两距离只有276对，先上限控制；不因节点增多直接上空间索引 |
| 单帧特效CPU绘制p95 ≤2ms（目标机，正常前台）；无特效引发的 >50ms 长任务 | Performance标记/调用栈区分effect绘制和笔记操作；同条件关/开各测3次。4×CPU节流下记录结果、优先降节点/帧率；不能用节流结果冒充目标机实测 |
| DPR候选上限1.5，内部buffer ≤250万像素；不运行全屏连续blur/Bloom | DevTools/尺寸日志检查canvas width×height，Windows缩放100/125/150%逐项查看。需验证发光依旧清晰，不将上限值当视觉结论 |
| 系统减弱动效、用户停止、hidden、卸载时停止循环；恢复不跳跃 | 后台20秒再回来，帧计数/定时器/状态检查；停止后保持内容可读，StrictMode重挂载无双循环；关闭后不能visibilitychange自动重新开 |
| 1,000条×500中文字符的候选笔记集：查找到结果绘制p95 ≤100ms，开特效相对关闭增加≤20ms | 使用隔离临时数据，不导入替换用户数据；Performance/React profiler定位过滤与卡片render，冷/热各3轮。10,000条为压力观测，不先承诺支持；实际瓶颈后才考虑分页/索引 |
| 增量gzip JS候选≤10KB，无新粒子/3D依赖作为首选评估 | 改前后同构建方法比产物；基线ui-observations记录82.16KB gzip只是主代理回传，最终要再次构建对比。超预算则说明原因或缩减效果 |
| 动效帧不触发笔记持久化、不影响文本光标；开/关10次内存不持续增长 | React profiler、Application写入观察、Heap快照；持续中文输入与选区操作并行。不要逐帧setState全局、写localStorage/SQLite或申请新渐变/监听器 |

这些是供方案使用的测量门槛，不是已达标事实；渲染、耗电与GPU真实成本依赖用户电脑/WebView，CPU阈值不能等同于完整GPU性能保证。节点开关与性能降级策略需后续明确，不增加几十个用户配置。

## E. 稳定性缺口与最小验证代价

- package.json:6-14仅有build/check，无前端test runner；Rust `lib.rs:1-101` 无测试，Release.Testing.md明确0用例。TypeScript/cargo check只证明类型/编译，不证明格式往返、迁移、输入、筛选或数据安全。
