- A2：不新增 Note/SQLite/备份字段或第二保存路径；不上传笔记，不借此修复其他功能，不丢弃或整包发布来源未知的工作区改动。
- A3：不采用外部角色/模型、Live2D/Qt/WPF 宿主、通用宠物平台、养成经济或 OS 跨窗口追踪；不引入第二关系/物理引擎、Bloom、真实阴影或骨骼框架。

## 2. 总体思路与系统边界

新增一个只读可视层和一个独立宠物功能，以 App 的最小接入连接现有政策与业务入口。新模块可以拥有渲染副本、坐标、相机、选择与宠物会话状态，不能拥有另一份可保存记录。

### 数据与交互路径

1. App 持有 Note，沿用原活动集合与共享筛选；原本地关系请求通道供 2D 和需要关系的空间展示使用，保持旧请求取消、最新版本和重试行为。
2. 可见 UUID 经已有 `projectGraph` 投影，得到完整可见节点与两端可见的边。关系等待、失败或输入变化时仍保留匹配节点，清除已失效的边，不显示旧请求的关系。
3. 空间布局只把当前记录元数据和已投影关系转为派生三维坐标、分组色与显示大小。布局和渲染副本不修改 Note、GraphModel 或原 2D 会话。
4. Three owner 渲染并通过 UUID 输出选择；文字选择与详情保持同一 UUID，编辑回到 App 的最新记录复核及原编辑器。宠物行为不消费笔记内容。
5. App 只新增入口/视图编排、必要的关系启用条件和政策传递。2D 的 Ctrl K、相机/位置会话、排序和存储所有权保持原契约。

### 空间表达

- **关联星图**：复用现有 group 成簇，颜色表达分组，节点大小表达可见关联数量，完成状态另有可辨识表达。节点和关系均能由文字详情解释；共同标签事实与正文词面推断继续区分。稳定的派生排布用于减少切换与过滤后的无谓跳动，不运行新的力导向语义过程。
- **时间层**：创建时间提供一条明确的空间方向，分组与完成状态提供另外的视觉维度；页面说明所用时间是「创建时间」。时间方向、图例和选中记录的文本时间一致，不把几何距离解释为关联强度。无效时间的保留与说明需在低层方案落实，不允许因时间解析失败丢失 UUID。
- **宠物伙伴**：大尺寸展示角色与明确的轻触、休息/唤醒动作。该页不构造宠物与笔记的虚假联系。浮动小宠物与展示页复用同一原创表达及有限行为规则。
- 文字记录入口与详情位于普通 DOM；渲染失败和关闭动态时仍可查看、选择和编辑，不要求用户只能操作画布。

### 生命周期与失败边界

空间入口通过 lazy/Suspense 加载 Three 与 OrbitControls；记录、账本、旧 2D 页面和小宠物不加载 Three。模块加载失败、renderer 初始化失败或 WebGL context loss 都进入可理解的降级状态：停止自有调度、清理已获得资源，提供当前文字记录路径及返回原关联图的入口。显式重试须先结束旧 owner，避免重叠资源。

渲染 owner 对自有 RAF、事件、观察器、controls、renderer、共享几何/材质和自建资源负责；共享对象集中释放一次。初始化中途失败、StrictMode 重挂载、离页与 context loss 执行同一所有权原则。宠物 owner 同样取消定时动作、拖拽 capture 和本次反馈，不沿用旧 helper 的成功测试作为证明。

## 3. 关键决策与备选方案

### D1：直接 Three.js，按入口懒加载（G1/G3、A3）

**采用**精确锁定 Three.js `0.186.1`、类型 `0.186.0` 与官方 OrbitControls。官方已有旋转/平移/缩放和按需渲染模式，一个新增场景可由独立 owner 管理，既符合当前组件边界，也无需自建相机控制器。

**备选** R3F 能降低声明式场景维护成本、支持 demand 渲染，但本轮增加另一个 React renderer 层并无必要；不据此判断其性能更差。react-force-graph-3d 提供较完整图能力，但新物理/图状态和暂停时取消交互不符合「停自动动态仍可操作」边界。原 2D Canvas/D3 继续服务原图，无法承担真透视 3D，因此不以视差装饰替代目标。

**代价** 新增 Three runtime chunk、显式资源释放和 WebGL 兼容责任。实际 JS/gzip、precache、首次进入与重复进入资源观察归后续验证；npm 包解包量不作为下载成本。

### D2：本地关系、几何排布与元数据编码分离（G1/G3、A1/A2）

**采用**一份业务 Note、一份原关系模型与独立的只读空间布局。关系模式按已有 group 排布，时间模式按创建时间编码；过滤只改变可见投影，更新期间节点身份不随关系结果消失。空间不持久化位置，也不向关系模型写入三维坐标。

**备选** 新增 3D force engine 可提供更强物理动态，但带来重复布局状态、持续计算和难以解释的视觉距离；持久化坐标或新业务 schema 则扩大迁移/备份责任。本轮展示目标不需要这些成本。

**代价** 排布是设计表达，不能证明主题与关系质量；空间图需有图例和详情说明。LW Plan 要明确大小/颜色/完成状态的同一口径与切换稳定性，但不改变现有关系算法。

### D3：原创 SVG/Motion 宠物，显示与行为分层（G2/G3、A2/A3）

**采用**本地原创 SVG 角色，既有 Motion/CSS 实现有限动作。借鉴成熟桌宠的显示/行为/宿主分层：角色表达不读业务记录；行为只处理呼吸、眨眼、目光、轻触、打盹、唤醒和拖动；宿主限制活动区域并给出暂停/模态政策。小形态与大形态共享角色，避免维护两套素材。

只有「是否显示」使用独立 localStorage 偏好；位置、情绪和短时动作留本次会话，不进入 SQLite 或备份。弹层期间浮动宠物隐藏或停在弹层后，取消交互并退出 Tab 序列，不抢正文键盘焦点；可通过清晰控件收起和恢复。拖拽只在角色/抓手使用有限手势区域，窗口变化时仍限制在晴笺可见区域。

**备选** Live2D 带来模型、Core 与动作资产的独立许可及加载链；移植 VPet/Shijima 代码或资产还增加原生宿主/许可责任；简单无状态装饰无法满足拖拽、休息与反馈。原创 SVG 保留可互动表现，同时缩短资产与生命周期链。

**代价** 表现力有限，不承诺成熟商业桌宠的动作量；需要亲自验证大/小显示、拖完不误触、取消与减少动态。角色造型可在用户回归验收时调整，不阻断当前授权内交付。

### D4：连续动画限额，静态交互按需渲染（G1/G2/G3、A1/A3）

**采用**一个空间 canvas，共享节点几何并批绘节点/边、有限粒子。自动旋转/呼吸等只在 App 动态许可、页面可见、无弹层且 owner 活动时调度；owner 自行承接 blur。关闭动态、系统 reduce、hidden、模态和取消事件均停止持续调度，恢复时重设计时基准。

静止仍可在合法交互时响应旋转/缩放、点选、筛选、主题和尺寸变化，仅为这些变化请求必要帧。OrbitControls 的 change 与 damping 调度去重，禁止同步递归渲染。模态/hidden 则停止本 owner 手势，不让背景画布或宠物穿透主操作。

**备选** 无限 RAF 和重后处理易快速获得持续动效，但增加静止耗电、资源与暂停责任；完全冻结 canvas 能省调度却失去静态交互。本轮以按需渲染加有界动态满足两类场景。

**代价** 调度状态与取消分支更需要验证。限额、批绘或代码审查均不能证明实际 GPU 流畅；实测以当前设备和有界输入为范围，不许扩大为普遍性能结论。

### 交接与实施顺序

1. readiness 检查需求映射、事实依据、接口与验证责任；LW Plan 逐项消费完整基线并通过 Gate-2。
2. WP1/WP2 在独立模块并行；共享 App/CSS/依赖/版本由 WP3 唯一 owner，新增依赖先顺序安装/锁定，禁止两包并发写锁文件。
3. 实施报告记录本包命令、完整输出、退出码和源码 SHA；纯函数/取消测试只支持相应逻辑结论，不冒充 GPU、真实 DB 或浏览器结果。
4. root 独立验证实际关联/时间画面、相机、选择/编辑、筛选、宠物动作/拖动/收起恢复、暂停、主题、390px、模态及原能力。随后冻结、低并行构建 Windows 制品并记录 version/hash 与自建进程烟测。
5. fresh reviewer 未参与实现，审查实际 89 基线差量、最终源、测试、完整根日志、当前文档和制品。审查后源变更必须重测复审；缺失现场证据标为未验证。

### 不可静默改变的下游契约

- 3D 布局不改业务 Note、关系依据、源数组顺序、备份或原 2D 图会话。
- 每个匹配 UUID 可通过画布或文字入口到达；关系 pending/error 与无效时间不删节点。
- 宠物显示偏好和会话行为独立于业务数据，不调用 AI 或读取笔记。
- 停自动动态保留合法静态交互；hidden/modal/blur 取消 owner 手势与持续调度。
- 源、日志、文档和制品身份一致；任何范围变化先重算完整基线，再通知下游。

本阶段没有新增跨功能事实；沿用 research.md 已列的候选事实，不重复建立事实条目。
