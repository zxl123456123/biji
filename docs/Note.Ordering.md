## 使用与分组

- 使用卡片右上角抓手移动。抓手提供键盘入口：空格/回车拿起、方向键移动、空格/回车放下、Esc取消，并配置中文操作说明与公告。正文、完成、复制、编辑、回收和置顶按钮各自保留直接操作。
- 置顶记录独立放在顶部，沿当前网格/单列布局和自身排列展示；它们不按日期拆组。置顶按钮只切换状态，不挪动底层数组；取消后回到当前规范位置。记录置顶与固定标签是两个功能。
- 网格、阅读的普通记录在普通区内排序；日期模式只在同一日期的普通组内排序。置顶区可在自身内排序。跨置顶/普通区或跨日期组移动被拒绝；改置顶要用按钮，排序不改计划日期。
- 搜索、标签和未完成条件共同作用于两区。置顶优先后普通记录共用首批60条，加载更多每次增加60；不是两个区域各60条。日期标题、置顶计数指当前批次显示数。
- 回收站不提供排序或置顶入口；软删除、撤销与恢复保留原记录的置顶字段和规范数组位置。

## 一个顺序来源

完整Notes数组包含活动、隐藏、未加载和回收站记录，是顺序的唯一权威。展示时稳定分开置顶/普通；普通日期组按日期倒序，组内仍按该数组顺序。没有第二份前端ID偏好表，也没有公开sortOrder字段。

合法放下后，将该组当前可见ID的新顺序合并回它们在完整数组中的原槽位，其他槽位和原记录对象保持。最新完整数据会再次核对预期ID顺序、唯一性与合法组；过时、缺失、重复、取消或无变化不提交。筛选结果不能整体覆盖完整数据，因此不会因为看不见就丢掉记录。

排序/置顶只改排列或pinned，不改正文、创建/修改时间、计划日期、完成状态或账目。新建仍前插，编辑沿原对象合并。图关系仍依据id/content语义快照，手工排序不是图节点的持久坐标；图拖动继续使用原D3通路。

## 拖动、动效与取消

排序采用精确`@dnd-kit/react`和`@dnd-kit/dom` 0.5.0。卡片根和独立抓手连接公开ref/handleRef；各合法组使用type/accept隔离碰撞候选。纯预览浮层不注册sortable，也不复制业务按钮。

库在拖动期间临时调整DOM；应用仅在合法结束时更新Notes，沿原保存effects持久化，不逐帧写本地存储或SQLite。鼠标结束还使用本次pointerup最终坐标核对合法组当前矩形与视口的交集，不能只信上一次碰撞目标；键盘不用鼠标落点判据。

关闭动态效果或系统减少动效，只关闭排序过渡与落下动画，业务抓手仍可用。编辑/快开/标签/AI弹层、后台会限制业务启动；筛选、排版、批次、数据变化、离开页面、失焦、后台和卸载进入取消边界。

取消先使旧会话失效。Provider外的SortLifetime在父级layout cleanup中先使owner/session失效并公开stop canceled；随后同次子Provider的insertion cleanup销毁manager/活动sensor，重建使用新manager。只让应用finish回调return挡不住库Renderer更新，提前停止活动操作才避免在insertion cleanup中触发它。临时DOM回到权威排列，无效旧回调不写Notes。

应用自身blur/visibility监听有清理；固定库存在一次性的window noop touchmove补丁，不宣称库全部全局监听均被删除。键盘放下/取消会等待本次合法提交落地再恢复抓手焦点，弹层/导航/失焦取消不抢焦点；本轮Enter/Esc绿例不能替代原生后台与读屏验收。

## 本地保存与旧数据

Web仍保存完整数组，JSON备份仍version1；`Note.pinned`为可选布尔，缺失视false，数组承载顺序。旧导入替换整份数据、原JSON字段校验和空桌面库回退属于原行为，本轮没有顺带改写。

桌面SQLite只幂等新增元数据列：`pinned INTEGER NOT NULL DEFAULT 0`、可空`position INTEGER`。旧7列先补原deleted_at，旧8列补新两列；未有手工位置的记录保留NULL。加载按有位置优先、position升序，再以创建时间倒序/id升序回退；旧同创建时间的相对顺序历史上未定义，不承诺保留该未定义顺序。

保存仍是一笔事务：完整数组包含回收站，按数组索引写position，笔记和账目一起成功后提交。任一步失败不能留下半份排列。生产初始化/读取/写入helper也是数据库测试的入口，没有另写一套测试迁移逻辑。

**降级边界**：旧版EXE写回新数据库会忽略或丢掉新pinned/position，因此不保证旧版本写入保留这些元数据。迁移仅ADD列；出现异常先停止新程序写入，保留库和备份，不自动删除列或覆盖恢复真实用户库。

## 选型与证据边界

采用现成的抓手、键盘、公告、临时排序与取消生命周期，避免自行补全手势状态机。[现代useSortable](https://dndkit.com/react/hooks/use-sortable/)与[排序状态管理](https://dndkit.com/react/guides/sortable-state-management/)提供主通路，但实际接口以固定0.5.0发布物为准。最初legacy候选因公开外部取消与活动sensor清理证据不足被替换；已有Motion14支持二维，本轮不采用其Reorder的原因是还需补键盘/读屏/取消和结束后保存，并非它不能做网格。

元数据与正文分离参考[Joplin order字段](https://joplinapp.org/help/api/references/rest_api/)；本项目采用数组投影，未照搬其秩算法。兼容仅使用既有[SQLite ADD COLUMN](https://www.sqlite.org/lang_altertable.html)与[事务](https://www.sqlite.org/lang_transaction.html)，不引入同步/CRDT或新备份协议。研究和取舍入口见[本轮调研](current/note-order-and-pinning/research.md)。
