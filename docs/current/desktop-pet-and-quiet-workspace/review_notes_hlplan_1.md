## 可行性分析

- 用户目标已纠正：实际桌宠替换、Windows 独立活动和简洁工作区可追溯到原话。没有沿用正文装饰作为主目标。关闭沿用退出和有限实用动作明确属于协调者实现选择，未伪称逐项用户答复。
- 单一 main 保存者与独立 pet 入口是必要设计：`main.tsx` 目前无条件挂 App；`App.tsx:90–91` 加载并保存三类数组；Rust `save_to_connection` 会 DELETE 后完整写入。因此禁止 pet 挂 App，加实际 caller label 门禁有事实依据。
- Rust 创建固定隐藏伙伴窗可用。安装源有 `transparent`、`focusable`、`skip_taskbar` 和 `on_window_event`；AppHandle 有 exit；API 的 Monitor.workArea 为排除任务栏的物理坐标。方案没有把这些类型/源码事实当作原生透明或焦点验收。
- 三个内容包边界清楚。小型窗口、复用已有快记/待办、低频有限活动和现有 GLB renderer 足以实现首版，不需要平台式状态机、全局监听或第二套数据。
- 本机五角色映射、缺文件 SVG 回退与装扮真实节点判断能解决生产仅原创 GLB 的现状；保留候选资产和多视角证据适当，视觉满意度仍由用户判断。

## 阻断修订项

### H1：一次/日提醒没有完整确认链路

具体内容：§5 说“协议限当前功能的三类消息”，用户意图只列“快记、待办、收起”，快照没有待提醒资格/提醒身份字段；同节却要求“由 main 确认展示后记录已有日期键”。已读 `App.tsx:93–94` 的旧提醒判断和记键只依赖主窗 `todoReminder`。新的 pet 展示不会设置该变量。

影响：若 pet 只读到期数量，重载可重复自动提示；若 main 在发布时立即记键，隐藏、加载失败或休息时可消耗未展示提醒；若仍运行旧主窗 effect，两个窗口会同时自动提醒。LW 必须自行发明第四类确认消息或扩展第三类，属于公共契约缺口，不能只靠“后面明确事件名”放行。

恢复动作：给快照增加当前本机日期的提醒资格和一个可核查身份；明确 pet 只有真正显示局部提示后回传展示确认，main 校验日期/身份与当前资格后写既有日期键，再发布更新；允许将确认并入现有有限意图枚举而非造新总线。明确隐藏/休息/重载未展示不记键，桌面模式禁用主窗旧自动弹层，显式打开待办不受一次/日限制。LW 再细化字段名和去重时序。

### H2：协议 ready 与失败回退的定义没有落到现状

具体内容：§4 要求“尚未加载数据、初始化失败或主窗未建立协议时，pet 保持隐藏”，§5 又按“数据 ready”发布。现有 `App.tsx:90` 在 SQLite 加载失败的 catch 中同样 `setReady(true)`，随后保存 effect 会启动。

影响：若复用当前 ready，数据库初始化失败仍显示 pet，与高层边界矛盾；若把当前 ready 改成 false，可能改变既有浏览器数据回退和编辑路径。这两种行为不能交给 LW 自行猜。

恢复动作：显式区分已有业务 UI ready 和伙伴 protocol-ready；说明 SQLite 失败但本地浏览器回退可用时，是允许主窗继续既有回退而伙伴隐藏，还是按明确定义发布可用摘要。依据本版 §4，最小修改是主窗保留现有回退、仅伴侣协议保持未就绪/隐藏，并让恢复行为可观察。无需新增用户问题或 schema。

## 其余风险与 LW 必须消费的约束

- 摘要 revision 在当前运行单调，但 main 前端重载会重置计数：LW 应由 Rust 分配 revision 或读取现有值后续增，不能让热重载后的 main 永远被旧 revision 拒绝。pet 要监听后读取并拒绝晚到旧响应。
- 动作还需主窗处理结果/错误的明确返回口径。Rust 能 show/focus 不等于快记真正打开；重复标识、阻塞编辑器保留和超时后按钮恢复需形成闭环。
- `focus:false` 只有初始含义，方案对此正确声明。LW 应具体决定是否采用 `focusable:false` 并核验拖动和菜单可用性；原生切回其他应用时不抢输入仍是 coordinator 验收项。
- 人工拖动所有者、onMoved 稳定检测、取消中的晚到 setPosition、多屏负坐标和 scaleFactor 换算需落到可验证函数；不可假定 startDragging Promise 等到松手。小透明宿主区域透传未验证，不宣称逐像素穿透。
- 模型契约已有 idle/happy，没有 walk/rest clip。采用窗口短距活动并诚实命名合理；三维衣橱配件、非原创身体色保留和缺节点时隐藏控制需验证实际效果。
- 旧 token 保留固定不可编辑 host 和受限序列化合理；不保存任意 HTML，不全库迁移。需要确切删除嵌套 root/按钮清单和保存往返、草稿、Backspace/撤销测试。
- 内容区单一纵向滚动 owner、标题连续与更多菜单要手测焦点、窄屏和弹窗；不能仅删文字称界面满意。
