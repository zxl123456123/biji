## 头脑风暴决策

**用户确认：✅ 目标与聚类语义已由最新要求及选择题确认。** 技术细节按“分析选择”的明确授权收敛，沿已授权持续开发推进各阶段，保留独立评审。

1. 把主界面轮廓真正改成轻盈通透的记录工作台：紧凑可发现的导航/新建/搜索、宽内容、网格记录与可选日期分组；有明确真实脑图入口和足够大的画布。炫彩光场/渐变边缘/透明表面在主体可见，正文保留稳固对比底色。旧日期导航不恢复。
2. 每条未删除记录恰好一个节点；标签共现与本地正文词面相似分为事实/推断关系，孤立记录保留，图例和详情可解释。颜色和空间分组有确定依据，不把随机连线作为知识关系。
3. 优先D3成熟force/zoom/drag能力+Canvas可控绘制；高层方案正式收敛最小依赖组合与暂停/输入边界。RFG2d作为比较备选，不保留双引擎。Sigma/Graphology/ReactFlow未证明必要；不为了炫彩引入3D/VR/远程模型。
4. 图是笔记的派生视图：App唯一notes负责保存；纯关系构建与图ref/绘制分开；选择节点id复用NoteComposer。相似和分组不在绘制帧或pointermove重算；较长计算用有界Worker，须处理过期响应。保存/增删/恢复更新图，保留同id内存位置及用户镜头。
5. 持续视觉可以是光粒流动/节点呼吸；物理布局可冷却，减少目标漂移。暂停、系统减弱、后台、编辑时边界明确；停止动态仍保留点选/缩放/拖拽及文字选择入口，不让Canvas成为唯一访问途径。
6. 不新增手动关系表、坐标持久化、完整语义模型或迁移；本地n-gram/TF-IDF等成熟词面原则依据研究选择，标签稀疏关系子集和推断需如实说明。性能实测后说明预算是否达到，不给零bug/所有GPU丝滑承诺。

## 完整实现基线

### 目标锁

G1. 在真实运行项目里提供明显区别于侧栏单列旧界面的炫彩通透工作台、网格/日期记录排版、可见且克制的动态、浅深/窄屏与可操作编辑；不得只交候选HTML或边缘光粒。

G2. 真实记录节点集合对应筛选后的未删除笔记，标签/本地正文相似形成可解释的稀疏连线和聚类；支持点选预览/编辑、拖动、缩放、回到全图、关联高亮、过滤以及增删修改后更新，孤立笔记不遗漏。

G3. 使用研究过的成熟布局/交互能力，关系计算/绘制/持久化职责分离；保持本地纯文本、草稿、回收站及现有数据/未提交工作。经过独立方案/实施审查、真实交互和动态可见证据、构建/测试后产出新的Windows EXE。

### 反目标

- 不再次把低对比随机边缘点称为脑图；不以“UI看起来专业”代替用户明确要求的可见炫彩/排版变化和真实关系。
- 不自动上传笔记、直接持久化/渲染任意HTML、不复制整套知识库/插件架构，不默认远程embedding或完整3D。
- 不每帧setState/构图/保存，不构造无上限全量成对边，不静默只显示前若干条笔记；不覆盖初始工作、不提交生成物/密钥、不强推。

### 风险边界与验证责任

- architect/planner：消化research.md当前源码及官方GitHub事实，选唯一技术路线、解释选择/拒绝理由；给明确节点/边/分组规则、输入/暂停/镜头与Worker响应合同、可回归样例。不把候选性能预算写成已达成。
- impl：按分离的整理/功能工作包修改源码，使用小依赖并锁版本，执行纯关系测试/原12项/Web构建，记录完整输出/退出码；不得访问用户UI、凭据或真实数据库，真实浏览器/EXE由root承接。
- reviewer：readiness、Gate2、ReviewImpl独立读最新基线/代码/测试/证据，尤其检查数据mutation、孤立节点、标签大团、相似误导、静态图仍可操作、异步旧结果及资源清理。
- root：独立运行检查；以隔离夹具实际验证网格/时间/浅深/窄屏、节点选择编辑/新旧内容/删除恢复/筛选、缩放/全图/暂停与持续效果；保存改前后实际项目截图，测量可行的构图成本/包体；Windows构建/版本哈希/启动/旧库保留。原生IME/缩放/触屏/后台或GPU未可实测时如实限定。
- 性能目标依据research候选与方案落地结果制定；测量不足不能宣称所有设备丝滑。若成熟引擎需要额外依赖导致预算变更，说明真实构建结果，不捏造gzip。
