## 已知用户说明

- 顶部黑色区域位于整个桌面窗口顶部。
- 宠物应能作为打开笔记的快捷入口，并提示当天待办。

## 头脑风暴决策（待用户对交互口径确认）

1. 待办清单采用独立条目，普通笔记的日期与完成状态不自动转成待办。两者继续通过现有笔记入口互相跳转，不复制正文。
2. 伙伴提示采用应用内浮层，每个本机日期首次打开时提示一次；点击伙伴可主动再次查看。提示只读本地待办，不调用 AI 或网络。
3. 顶部采用 Tauri 官方自绘标题栏模式，保留拖动、最小化、最大化、关闭及键盘可达性。必须先以隔离数据环境做原生 GUI 验收。
4. GitHub 找到的角色模型授权不明；不复制进产品，保留当前代码绘制角色。

## 完整实现基线（待确认）

### 目标锁

- 桌面端窗口顶部与应用页眉形成连贯界面，原有窗口控制、拖动与响应式操作可用。
- 独立待办可添加、修改、完成、删除、按日期查看；伙伴显示今日未完成事项并可打开笔记。
- 浏览器本地存储、桌面 SQLite 和备份包含待办，旧笔记与账目数据保持。

### 反目标

- 不把所有未完成笔记自动视为待办，也不把第三方无明确许可的 3D 模型打包。
- 不新增账号、云同步、AI 自动提取或后台系统通知。

### 风险边界

- 现有工作区未提交内容必须保留；旧 EXE 不得写入迁移后的新数据。原生窗口和数据迁移需隔离实测。
- 3D 模型需另有来源和角色授权证据，本轮不把未知授权当作可使用。

### 验证责任

- 实施者运行测试、Web 构建和 Rust 数据测试；coordinator 在最终源码执行 fresh 验证并记录退出码、完整输出与失败。
- 原生标题栏需实际 GUI 验收拖动、最大化、最小化、关闭、缩放与浅深主题；缺证据只能标注未验证。独立 reviewer 检查最终差量。
