## A. 系统边界与现有能力

- React + TypeScript 提供账目创建、编辑、删除。人民币展示使用 `Intl.NumberFormat`，仅一种收入/支出记录模型；没有账户、银行同步或资金余额模型。
- 浏览器账目保存在 `localStorage`；桌面主窗通过 Tauri 调用 SQLite。JSON 备份包括笔记、账目与待办。
- 只有用户主动向 AI 提问时，`AiPanel` 才组装本地摘要。账目摘要日期取 `createdAt`，没有其他日期源。
- 月结余只是所选收入减支出。当前代码没有起始资金，更没有把每月结余加进总资金的逻辑。
- 用户撤回后不需要资金概览二级入口、余额自动扣减或金额隐藏能力。

证据：`src/types.ts:28-51`；`src/App.tsx:260-262,382-391`；`src/store.ts:38-67`；`src/desktop.ts:6-7`。

## B. 入口与主流程

1. 主导航账本入口是 `src/App.tsx:340`，顶栏“记一笔”由 `createInView` 打开交易表单（188、354 行）。账本空态也有创建入口。
2. `App` 用 `selectMonth(transactions)` 获取本月记录，`monthTotals` 聚合。这里没有可选期间状态（180-183 行）。
3. `Ledger` 展示本月标题、三张统计卡、前四个支出分类和流水。流水直接遍历传入数组，未独立按日期排序（382 行）。
4. `LedgerComposer` 只收金额、类型、分类、备注，编辑时回填这些字段；没有日期输入（384 行）。
5. `saveTransaction` 新建时把当前 ISO 时间写入 `createdAt`、`updatedAt` 并插入数组头；编辑时保留原 `createdAt`，更新 `updatedAt`（260 行）。
6. 状态变动触发 `persist`，将完整笔记/账目/待办快照串行保存。桌面读取成功后使用 SQLite；失败时保留浏览器回退（43-49、128-137 行）。
7. 备份按完整数组导出；导入替换笔记和账目，旧备份缺少 `todos` 时保留当前待办（261-262 行；`store.ts:64-67`）。

## D. 日期、数据兼容及传播事实

### 日期的实际用途

`createdAt` 字面意思是创建时间，当前还承担账目发生日期：月份筛选、流水日期、AI 摘要及 SQLite 排序都使用它。`updatedAt` 只在保存时更新，没有参与期间筛选。

`selectMonth(items, now)` 已允许调用方传入指定 `Date`；它使用 `getFullYear/getMonth` 的本地时间，不修改数组，保留来源顺序。非法日期自然被排除。`dateKey`/`today` 已有本地日历日期工具，日期文本不能简单用 UTC `toISOString().slice(0,10)` 替代其本地语义。

### 复用 createdAt 的可行性与代价（事实及推断）

- 事实：所有保存层把 `createdAt` 当字符串透明传递，没有检查“必须是现在”或“必须是本月”。
- （推断）若其业务含义明确成为账目日期，历史补记可经现有字段传播，不必仅因增加日期选择就增加 SQLite 列或备份字段。
- （推断）这样会失去“补记发生在何时”的独立创建时间语义；`updatedAt` 表示最后修改，不能永久替代创建时刻。
- 事实：旧账目 `createdAt` 是实际录入时刻，无法从现有数据还原用户忘记填写的真实消费日期。保持旧数据意味着默认沿用该日期，而不是猜测或批量重写。
- 事实：SQLite 按 `created_at DESC` 排序；浏览器按新建插入数组头。发生日期能改变后，两个来源的数组顺序可能不同（推断），不能把数组头当作日期最新。
- （推断）把日期保存成裸 `YYYY-MM-DD` 后再 `new Date` 会触及 UTC/本地差异；保留现有可解析时间格式和本地年月语义，是需要验证的兼容边界，不是本调研批准的编码方案。
- 若独立新增发生日期字段，现有 Rust `Transaction` 没有对应字段，JSON→Rust→SQLite→JSON 不会保留它（推断，依据固定结构和显式 SELECT/INSERT）。这条路线会扩大到 schema、serde、查询与旧库回退。

### 存储与桥接

- 浏览器：`luma-transactions-v1` 保存整个数组，读取直接 `JSON.parse`。账目不是附件 IndexedDB 的一部分。
- 备份：version 固定为 1；导出透明保留账目字段。导入没有逐条验证账目的日期/金额。该既有校验缺口只记录，本调研未修改。
- Rust：`#[serde(rename_all="camelCase")]` 将 `created_at` 映射为 `createdAt`。当前 transactions 表七列，读取明确七列，插入使用无列名七值语句。
- SQLite：`save_to_connection` 在单个事务内删除并重插 notes、transactions、todos。交易保存也是完整应用快照写入，任何字段遗漏都可能影响其他域；已有插入失败回滚用例说明这些表共用事务。
- 主窗：`useMainPetBridge` 的 AppData 成功读取后直接交给 `commitData`，App 整体设置三组状态。账目不是宠物摘要中的共享项目；宠物不直接持有账目写入权。
- `load_data/save_data` 要求主窗标签 `main` 以及原生启动 ready。新账本视图不构成新增跨窗数据流需求。

## E. 业界资料与相关边界

- [Restarting Your Budget](https://actualbudget.org/docs/advanced/restart/)：作为原资金方案背景复核；其重启预算目标与晴笺保留旧记录并补记历史不同，没有必要引入重启/删历史流程。
- [Importing Transactions](https://actualbudget.org/docs/transactions/importing/)：“Manually Add Transactions” 展示先进入记录入口、填完整交易再添加的流程；其日期同步说明将交易日期对齐实际交易有助于按时点核查。可参考“交易日期可表达实际发生时点”的语义，不照搬银行同步、CSV 导入或重复匹配机制。

这些资料支持把收支与日期关联；它们不替代本项目数据兼容验证，也没有给本次月份/年度具体页面布局作决定。
