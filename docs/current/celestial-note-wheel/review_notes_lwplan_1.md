## 风险点

1. **入口生命周期与过度设计**：`src/NotesView.tsx:24-25` 的 `limit` 是组件状态，`src/App.tsx:189-255` 的 `viewContent` 排他渲染。S2 `lwplan.md:90` 指定新 `View='wheel'`、提升 `limit` 到 App、保存 `.workspace` 滚动并 RAF 恢复；同包 `:92` 又允许保持列表挂载。这把一条卡片的临时可视化扩成 App 列表分页状态与滚动状态改造，且未锁定一种目标结构。保留 `view='all'`、让 `wheelEntryId` 驱动大画布覆盖层、保持 `NotesView` 挂载，可自然保留 `limit` 与 `.workspace` 滚动；需禁止背景交互、处理焦点与 Escape，并确认覆盖层布局不会缩小画布。若坚持独立 View，应给出它优于覆盖层的可核查理由，并只保留一个确定实现。
2. **动态默认值与视觉目标冲突**：S4 `:112` 写“默认行为遵守现有空间静态优先策略”；实际 `src/SpatialNoteMap.tsx:75` 初始 `paused=true`，`src/spatialRuntime.ts:1-3` 把 paused 纳入 continuous。照此执行会打开即静止，用户要借鉴原作“平面到立体往复、差速、聚焦”的第一印象不成立。应锁定首次入场是否自动展开、何时进入往复、默认暂停状态及退出/重开重置方式；系统减少动态、全局关闭、失焦、隐藏、弹层仍应压过自动动作。至少要有一次可验证的默认视觉动作或明确的显眼启动控件与验收口径。
3. **拾取预算仍缺目标形态**：S4 `:110-116` 约束共享 365/366 实例、低上限标签、30fps/DPR，但未说明在十二圈旋转/倾斜时格位实例矩阵何时更新、射线命中与文字日期如何保持一致、圈名/日期刻度究竟如何可读。`slots` 片段仅证明稳定索引，不证明选中格不会因运动角度与遮挡误点。应补一个场景结构/变换与视觉验收骨架：格位、环基座、月份/刻度文字的绘制预算；旋转状态下点击与文字清单的一致性；悬停/遮挡/触屏边界。固定资源上限和设备帧时证据继续保留。
4. **WebGL 降级路径基本完整，但导航与焦点需闭环**：S3 文字日期/记录清单在无 WebGL、context lost 下保留，符合基线。S2/S3 尚需锁定 overlay 或独立 View 的焦点进入、背景不可操作、Esc 关闭优先级、关闭后焦点回入口按钮；目前“按实际优先序接入”不足以直接实施。`src/App.tsx:106-119` 已有 Escape 的 composer/quick-open/AI/todo 分支，可据此写明确插入位置。
5. **工作区保护**：`git status --short` 显示已有大批已修改与未跟踪文件；计划有禁止清理与核查 diff 的原则，但 S5 的“本功能能辨识的改动才提交”需落成操作口径：记录实施前相关文件基线 diff、逐 hunk 审查，无法分辨时停止暂存并由 coordinator 处理，不能对共享文件整文件 `git add` 后把既有修改捎入提交。

## 修订建议

1. **优先修 S2**：确定一种列表生命周期方案。推荐 `view='all'` + `wheelEntryId` 的大画布覆盖层，保持 NotesView 原挂载与 limit，避免滚动快照；关闭后焦点回入口按钮。覆盖期间背景需 `inert`/不可聚焦并禁排序，防止底层操作。若仍用独立 View，删除覆盖层备选并给出 limit/scroll 方案的必要性及精确片段。
2. **修 S4 动态契约**：明确初次进入的动画时序、默认暂停值、自动往复与手动展开/收合的关系、重开复位、减少动态/全局开关优先级；把“能在默认许可下看到核心动作”列入人工验收，同时保留静态文字/日期操作。
3. **补场景最小闭环**：用目标伪码或简图说明月份环、日期格、标签/刻度资源预算；环变换后 raycast 命中和稳定 key 的关系；遮挡、空日、触摸与选中高亮的判定。把 context lost/重试与 model 更新纳入验证锚点。
