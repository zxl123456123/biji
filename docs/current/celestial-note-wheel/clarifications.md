## 头脑风暴决策

1. 入口放在“我的记录”的单条记录操作中，以大画布查看；现有编辑器、正文序列化和 SQLite 不新增可视化块或字段。
2. 中心对应当前笔记，十二圈一月至十二月。每格对应当天实际日期；无记录日保持低亮度，有记录日按条数提示，与中心笔记有当前本地关系图直接关联的记录另作强调。标签、关系依据与完整正文仍由已有数据和原入口解释，不把日期接近冒充语义关联。
3. 点击日期显示当天真实记录清单；选择记录后打开原记录。关联计算未就绪时仍能查看日期和记录，并明确关联状态。
4. 视觉借鉴参考项目的程序化字格、同心环、平面到立体的往复、环间差速、相机和有限光晕；不复制术数符号、推断或代码打字机。动效服从系统减少动态、晴笺动态开关、页面可见性和弹层状态。
5. 借用晴笺现有 `three` 依赖与本地关系模型，不新增远程请求、持久化 schema 或第二套关系算法。

## 完整实现基线

### 1. 目标锁
- 单条笔记可打开一个十二重、以真实月份/日期建模的交互年轮；任一日期与记录均可由用户核对，不出现虚构内容。
- 保留参考作品最关键的视觉动作：同心层、差速、平面与立体往复、聚焦反馈，同时能停止动态并继续用文字操作。
- 使用现有记录 UUID、创建时间和本地关系结果；选中后进入原记录流程，不改变内容、顺序、备份与云传输边界。

### 2. 反目标
- 不把《周易》内容、卦象或算卦逻辑带入晴笺。
- 不把无数据的装饰圈冒充笔记关系，也不因日期接近声称两条笔记语义相关。
- 不直接移植参考代码里的逐格贴图/常驻 60fps/全局指针监听模式，绕过晴笺已有资源和动态预算。

### 3. 风险边界
- 当前工作区有大量用户既有未提交改动；不得清理、还原或一并提交。最终提交须只含本功能能辨识的改动；推送前审查全部待推送提交。
- Web 构建不能替代真实 Windows WebView、弱 GPU、长时重复打开或完整鼠标/触摸体验的实测；缺失证据需明确标记。
- 后续若改变入口、日期范围或视觉强度，应先更新本基线并重新核对方案。

### 4. 验证责任
- 实施者：在 `impl_report_r1.md` 记录本轮新鲜的 `npm run build`、相关测试与实际界面检查的命令、退出码、完整失败和结果；另在 `verification.md` 按浅/深色、少量/大量记录、日期/记录点击、键盘、减少动态、Windows WebView、连续重开与长时性能逐项记证据或明确“未测”。
- coordinator：独立复跑关键验证并核对输出，安排实际界面体验；对于当前无法运行的 Windows WebView、弱 GPU 或长时场景，在 `verification.md` 写明承接人、复测步骤和未测状态，不以 Web 构建代替。
- 独立审查者：在实施者报告和 coordinator 的新鲜验证之后读取最终 diff、`impl_report_r1.md` 与 `verification.md`，检查数据真实性、动态/资源边界及全部失败；若后续修改代码，旧审查失效，重验后再审。
- 只有有实际证据的项目可称“已测”。缺少设备、观察或资源测量时保持 `unverified`/“未测”，交给用户或具备设备的后续验收，不能作为通过证据。

### 6. 基线生成规则
- 本基线从本目录 `README.md` 的原始需求出发，吸收 Q1-Q4 与最终方案确认；下游不可只引用头脑风暴决策，必须读取本完整基线。
- 原需求中的“嵌入笔记”由用户确认为单条记录的可选入口；“不用算卦”由真实日历与本地笔记关系承接；“原版视觉”由十二圈及其关键动作承接。

### 7. 基线内容边界
- **范围**：仅当前未删除笔记及其创建年份的十二个月、真实日历格、现有图谱的直接邻居；所有状态为派生展示，不新增持久化字段。
- **现有系统边界**：入口和 UUID 导航由 `App`/`NotesView` 持有；关系由 `useNoteGraph` 派生；可视化与文字清单共享日期模型；编辑仍进原 `NoteComposer`。
- **验收边界**：12 个月与 365/366 个真实日期、无记录日为零、关联标记不越过现有边、从日期清单到原笔记可用；视觉必有十二圈、差速、平面/立体转换、聚焦和有限光晕。Bloom 后处理是实现选项，不是唯一合格方式。

- `review_plan` 显式复核真实数据、视觉动作、资源与动态许可、文字降级、验证证据和可读性。
- `impl` 在改动前核对上述锁与边界，在报告中说明实际完成范围；不能把计划、构建或作者自述写成现场验收。
