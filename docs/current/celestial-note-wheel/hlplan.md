# 十二个月记录年轮：高层方案

2026-10-06。依据 [完整实现基线](clarifications.md)、[代码库调研](research.md)与用户已确认的十二个月模型。本文件描述待实施方案，不表示功能已经落地。

## 目标与非目标

从“我的记录”中一条未删除笔记打开独立的大画布年轮。中心始终对应入口笔记，其**创建年份**的十二个月依次占十二圈；圈上每个格位对应一个有效的公历日期。当天真实记录数可查，与中心笔记存在当前本地关系图**直接关系**的日期另行强调。点日期展示当天真实记录清单，再点 UUID 对应的记录进入现有原记录流程。静止、键盘和无 WebGL 情况下仍可完成同一导航。

不在正文中保存可视化块，不更改笔记、SQLite、备份、排序或关联算法；不加入术数内容、远程请求、按日期距离推断的关系。月份刻度表达日历，不把空日期画成有记录，也不把聚焦动画解释成关系强度。

## 背景与系统边界

- `App` 是记录状态与入口导航 owner；`NotesView` 只呈现当前筛选及分页批次，单条卡片已有操作区。年轮应由卡片传递入口 UUID，再由 `App` 从**全部未删除记录**取数，避免每批 60 条或当前搜索筛选造成全年统计缺失。筛选状态不隐式改变年轮统计，界面须注明“该年份全部未删除记录”。
- 当前 `useNoteGraph` 只在关联图与空间视图激活；年轮打开时才需启用同一本地派生模型。`projectGraph` 等已有模型负责关系依据，年轮只读取中心 UUID 的直接邻居，不自行新增相似度推断。分析更新或失败时保留日期、数量与清单，关系强调暂不出现并给出状态。
- `recordGardenModel` 已提供有效日期键、创建日期归组和月份天数。年轮使用相同的日期语义：记录创建时间转本地日历日；非法时间属于“日期未知”，不能塞进某个月。入口笔记本身创建日期无效时，没有可确定的中心年份，应显示文字说明并提供原记录入口，不猜测当前年份。
- `SpatialNoteMap` / `spatialScene` 已证明 Three.js、懒加载、动态许可、拾取、资源 owner 与文字回退在项目中可用，但三维空间的节点布局和场景不是年轮的日期模型。新年轮可复用这些**边界与策略**，不把现有空间场景改造成双用途引擎。

## 方案总体思路

数据流为：卡片入口 UUID → `App` 的活跃记录及本地关系状态 → 独立、纯派生的“年轮视图模型” → 3D 场景与同步的文字日期清单 → 日期选择 → 当天记录清单 → 现有编辑/查看入口。切换月份、点击日期和展开场景都只改变临时 UI 状态。关闭后返回原位置，进入记录时沿用现有 UUID 导航；入口记录被删除或数据更新时同步刷新可见结果，绝不保留幽灵节点。

模型固定十二圈，对应一月至十二月。每圈包含该月 **28/29/30/31 个真实日期格**，全图合计 365 或 366 个日期格。角度按该月实际天数均分；每个格位的稳定键是 `YYYY-MM-DD`，画面运动、相机角度和圈速不改变键与日期的对应。圈名、日期刻度和选择反馈必须可读。无记录日期为低亮但仍可选择并显示“当天无记录”；有记录日期显示数量级别或计数；直接关联另用形状/描边及文字标记，不能仅凭色彩区别。中心只承载入口笔记的简短、安全文本预览与日期，不绘制或持久化任意 HTML。

十二圈层次、环间差速、俯视与立体姿态转换、聚焦反馈以及**有限光晕**都是本轮视觉验收目标；运动是在**真实日期坐标上施加视图变换**。在交互选择时先固定对应日期的反馈和清单，避免旋转中的拾取误解。静止模式直接呈现可操作的平面状态。光晕克制且只帮助识别记录、当前日期或关联，不额外制造“数据”。

## 关键决策与备选方案

| 决策 | 备选与取舍 | 采用及原因 |
| --- | --- | --- |
| 年轮的数据范围 | A：当前筛选或首批卡片，入口直连但会遗漏记录；B：全部未删除记录，统计完整但与外层筛选可能不同 | **B**。全年视图必须忠实于真实日历与记录总集；显式说明范围。`App` 仍只提供本地数据。 |
| 圈内表达 | A：按记录数生成任意数量的字格，视觉密度跟数据变动但失去日期对应；B：每月实际日期固定成格，记录是日期上的状态 | **B**。用户确认每格对应真实日期；空日不会伪装成关系或“失踪”日期。闰年与月份长短天然可核对。 |
| 场景所有权 | A：直接移植参考仓库的场景、逐格 mesh/材质和全局监听，快速接近外观但突破预算与生命周期；B：独立、按需加载的晴笺场景 owner，复用现有调度、DPR、拾取与释放策略 | **B**。保持单一场景生命周期和 UI 数据分离，允许对格位批量绘制及稳定日期索引。 |
| 日期导航与退化 | A：仅 WebGL 点击，外观统一但键盘、失效设备不可用；B：场景与文字列表共享同一视图模型和选择状态 | **B**。可验证数据真实性，也让静止/键盘/无 WebGL 下保留完整导航。 |

## 与原作及 Three.js 的对应

原作 [场景源码](https://github.com/zaoxu001/celestial-wheel/blob/main/src/celestial-wheel.js) 以十二层字格、Canvas 字符纹理、差速旋转、相机转换、Raycaster 聚焦和 Bloom 形成视觉张力。采用其**环层节奏与相机叙事**；内容全部改为真实日期和记录，不复制固定典籍数据、随机反转赋义、逐格独立资源或常驻动画循环。原作 Canvas 图集只可作为少量月份/日期标签的设计参考，不应让每个动态日期与记录各自拥有纹理或材质。若需要许可或来源说明，应记录借鉴及原作 MIT 来源。

Three.js 的 [InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html) 适合对重复日期格共享几何/材质；[Raycaster](https://threejs.org/docs/pages/Raycaster.html) 可返回 `instanceId`，再通过稳定的日期索引还原日期。它们是绘制与选择工具，不承担业务模型。官方[资源清理指南](https://threejs.org/manual/pages/how-to-dispose-of-objects.html)要求显式释放几何、材质、纹理及有 `dispose()` 的控件/后处理对象。`UnrealBloomPass` 是实现有限光晕的可选手段；性能不足时可用材质、颜色与描边维持该视觉目标，并记录降级及视觉验收结果。十二圈本身若无法在目标设备运行，须回到上游重审目标，不得静默减圈。

## 生命周期、资源与可访问性

独立视图按需加载；退出后销毁场景 owner。与现有空间保持一致的动态许可：全局关闭动态、系统 `prefers-reduced-motion`、页面不可见、窗口失焦、弹层覆盖以及用户在年轮内暂停时，停止持续转动与自动展开；数据或选择变化仍允许一次静态重绘。动画时遵守现有空间的约 30fps、DPR≤1.5 与约 250 万像素上限作为起始预算。日期格优先批量绘制并保持有限标签数、共享资源；不可把每条笔记正文做成场景纹理，也不为装饰粒子建立随笔记数量线性增长的对象。重开、切换入口、失去 WebGL context 与组件卸载时应停止帧、观察器和监听并释放 GPU 资源。

同源文字界面至少提供：年份与月份导航、每月有记录日及数量、当天记录标题/预览及关联标记、返回原记录操作、分析状态说明。聚焦顺序和按钮标签应清楚；场景不是唯一可点击面。浅/深色、减少动态和低算力设备都要保持日期与选择对比度。选择某日但当天无记录时给出明确空状态。

## 风险与不确定性

- **U5 性能未实测**：365/366 个日期格、文字标签、十二个环同时动画，在 Windows WebView/弱 GPU 下的帧率和显存占用未知。先以批量日期格和少量标签做原型；测量后决定是否启用 Bloom，必要时停自动运动、改用低成本有限光晕，文字导航始终保留。若十二圈无法承载，应上报目标风险而非减圈交付。
- **日期边界**：ISO 时间在本地时区可能跨日；必须沿用现有创建日期分组语义，并以闰年、月底、时区跨日、非法时间验证。`scheduledDate` 不参与本年轮，因为基线指定创建年份与创建日期。
- **关系状态**：本地图谱会异步更新、可能失败，且关系边可能是词面推断。强调只在模型可用时出现，并在清单沿用已有关系依据的说明，不宣称因同日而有关联。
- **工作区保护**：当前已有大量未提交变更，含 `App.tsx`、`src/styles.css`、文档与新增模块。下游先核对 diff，只触碰本功能可辨识片段；不得清理或还原他人工作，提交时逐文件暂存本功能并在推送前审查 `origin/main..HEAD`。
- **真实体验未测**：构建成功不足以证明 WebView、触摸、键盘、长时间重开和资源释放。实施者在本专题的 `verification.md` 记录每项命令、退出码、完整输出位置、环境、操作步骤、观察结果和失败；coordinator 承接实际设备与人工体验，逐项补充已测/未测、责任人及未测原因。独立审查者按“最终 diff → 实施证据 → 人工证据”的次序复核，coordinator 最后裁定并移交未测项，不把缺失设备的项目写成通过。

## 向下游低层计划的拆解指引

1. 定义纯派生年轮模型：年份确定、十二个月真实日期、每天记录 UUID 与数量、直接关联标记、非法时间与分析状态；明确与现有日期模型的一致性测试。
2. 定义 `NotesView` 单条笔记入口、`App` 视图状态、活跃记录全集与本地图谱按需启用，以及关闭/回到原记录的导航流程；处理入口记录删除与数据变更。
3. 定义独立场景 owner：日期格批量绘制、稳定拾取映射、有限标签、平面/立体运动、暂停许可、尺寸上限、资源释放和 context 丢失。
4. 定义与场景同步的文字日期清单、键盘操作、关联状态与无 WebGL 回退；确保无动画也完成同样任务。
5. 实施者运行本轮构建与相关测试，并在 `verification.md` 留下命令、退出码、输出与模型/交互结果；coordinator 承接浅深色、减少动态、Windows WebView、弱 GPU、触摸/键盘和长时重开的人体验证或明确未测移交。独立审查者再读最终 diff 及两类证据；coordinator 根据审查结果判定剩余风险。实施后同步使用者文档、变更日志和项目进度。

## 可核查验收

- 任取一年，十二圈及每圈日期数与真实日历一致；2 月闰年为 29 格，其余月份 28/30/31 格；无记录日为零，点开不出现虚构笔记。
- 入口 UUID、中心内容、日期清单、记录数量和原记录导航一致；当前搜索筛选与每批 60 条不会遗漏全年记录；回收站记录不出现。
- 只有现有关系模型返回的中心直接邻居被标记；分析加载/失败时仍可查日期，且不显示过期关系标记。
- 暂停/减少动态/页面隐藏/弹层/失焦时没有持续绘制；多次打开关闭后帧调度、监听及 GPU 资源不累积。
- 禁用 WebGL、仅键盘、浅/深色及窄屏下仍可从年份到日期到具体记录；有限光晕在启用或性能降级后均可辨认。构建、相关测试、Windows WebView 与长时性能结果各自有证据或明确标为未测，不能互相替代。
