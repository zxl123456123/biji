## 头脑风暴决策

1. **存储**：每条笔记最多插入一个独立宠物块，写入受限的纯文本指令 `[[pet:xiaotuan]]`。只识别独占一行、字段完全合法且位于代码围栏外的指令。旧笔记和未知指令照原样显示。选择单行指令是为了沿用 `Note.content`、草稿、SQLite TEXT 和 JSON 备份，无需数据迁移；不采用持久化 HTML 或新附件表。
2. **编辑**：在普通正文光标处通过工具栏插入完整宠物块。编辑区显示不可编辑的三维晴小团卡片，DOM 转回纯文本时仅接受受控节点与合法字段。插入、删除、撤销依照现有浏览器编辑历史；输入法组合期间不插入。列表、引用、代码段内不插入，工具给出可见提示。
3. **阅读**：记录卡片、花园、图详情及拖拽预览显示同一位置的轻量静态晴小团预览；打开记录进入编辑区可见三维模型。装扮跟随当前晴小团设置；若全局角色切至其他角色，正文块仍显示原创晴小团并沿用当前衣橱配色和配饰。这样避免卡片按钮嵌套交互控件和大量 WebGL 上下文。动画遵循现有 `motionAllowed`，模型失败时回退静态预览。
4. **检索与复制**：纯正文抽取把宠物块读为「晴小团」，不把指令字段暴露给搜索与可见预览；现有「复制正文」复制可见文案。标签提取不把指令误认成标签。
5. **兼容**：现有数据结构可容纳新纯文本指令；旧 EXE 的读取和再次写入行为尚未实测，不能据此声称兼容。验证使用数据副本，不以现有用户数据库做破坏性试验。

## 业界参考与取舍

- [Tiptap Node Views](https://tiptap.dev/docs/editor/extensions/custom-extensions/node-views) 将文档原子节点的持久语义和交互视图分开；采用「受限文档语义 + 专用视图」这一做法。当前项目是原生 contentEditable，整体迁移至 Tiptap 会扩大编辑器改造范围，因此不引入编辑框架。
- [MDN contenteditable](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/contenteditable) 支持在编辑区内设置不可编辑的子元素；采用不可编辑宠物块，真实撤销和选区仍须验收。

## 完整实现基线

### 1. 目标锁

- 单条笔记可在普通正文光标处插入至多一个原创晴小团块；编辑区可见三维模型，保存、草稿恢复、重开及备份恢复保持块的位置和身份；装扮跟随当前衣橱设置。
- 卡片、花园、图详情和拖拽预览在相同位置安全显示静态预览；搜索和复制使用可见文本；模型失败有静态回退。

### 2. 反目标

- 不发布第三方角色模型，不存储任意 HTML，不新建附件/数据库结构，不重写编辑器。
- 不让笔记列表中的三维实例无限增长，不增加复杂插入配置。

### 3. 风险边界

- 原生撤销、选区、输入法、真实 WebGL/上下文丢失和旧 EXE 回写必须由真实环境证据支持。模型失效应回退到静态可见内容；编辑历史若不可靠，需收缩插入方式并重新评审，不得靠纯解析器测试宣称安全。
- 不在现有用户数据库上测试旧版写回；旧 EXE 兼容性缺证时明确标为未验证，由 coordinator 决定是否安排副本实测和发布限制。

### 4. 验证责任

- `impl` 在 `impl_report` 中记录纯文本语义、DOM 往返、草稿/备份、搜索/标签测试以及 Web 构建的命令、退出码与输出。
- `review_plan` 在实施后审查中独立核对格式、资源释放、安全渲染和范围约束；报告证据引用。
- `coordinator` 在 `verification.md` 承接真实浏览器手测：连续输入、插入/删除、撤销/重做、IME、保存回填、亮暗主题、降动效、模型故障与可见实例数；再决定是否以数据副本测旧 EXE/Tauri。
- 真实环境缺证时只能标明未测和风险，不能写成已验证或可发布。

### 5. 文档职责
