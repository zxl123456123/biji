# 三维宠物实现基线

## 用户决定

- 2026-10-06：需要真实三维建模，先选择原创晴小团。
- 随后用户扩大范围：把 Blender 下载到 E 盘，继续调研奶龙、吉伊、小八、乌萨奇并制作三维形象；现有二维重绘观感不满足需求。
- 2026-10-06 晴小团首版三维灰模正面预览后：用户选择「保留轮廓，继续细化」。该反馈只确认晴小团当前轮廓，不代表五角色成品与动作验收。

## 可执行范围

1. 使用 Blender 在 E 盘制作可编辑的五角色三维源文件，模型造型以晴小团现有原创画像及其他角色官方公开资料、用户既有参考图为依据。
2. 在晴笺中提供实时三维宠物预览，沿用现有轻触、休息、试穿、应用、动态许可与本机存储语义。
3. 公开发布制品先只包含原创晴小团三维模型。另四角色的三维资产先用于本机原型，待可再分发授权明确后才能进入安装包；现有 SVG 角色仍可使用。
4. 不新增笔记、SQLite 或备份数据字段；不导入网上第三方模型文件。

## 目标锁与反目标

- **目标**：五个可编辑 `.blend` 源模型及各自可检查的 `.glb`；晴小团在当前应用中实时渲染，至少在伙伴大展示和记录页浮层验证三维动作及外观。四个第三方角色在本机开发模式可分别加载并对比造型、动作，正式构建仍用现有 SVG。
- **反目标**：本轮不公开分发四个第三方 `.blend`、`.glb`、贴图或截图资源；不迁移本机外观存储格式，不改变笔记/账本/AI 数据；不承诺角色侧背设计与官方原件一致；不为全部小缩略图建立 WebGL 上下文。
- **验收粒度**：五角色分别核对正面、侧面、背面、眼脸比例、标志轮廓、idle/happy 区分；晴小团额外核对配色、头饰、围巾/蝴蝶结的试穿/应用。五角色灰模与精模由用户视觉验收，技术验收只证明模型与动作可加载、可用，不把独立建模解释为官方准确设计。

## 资产与发布边界

- 晴小团源模型可放 `assets-source/pets/`；需进入产品的原创 `.glb` 可放应用静态资源目录。
- 奶龙与三小只的 `.blend/.glb` 存放在仓库外的 `E:\pet-model-workbench\`，不得置于 `public/`、`src/`、Vite 依赖图或发布副本。开发模式通过用户主动选择本机 `.glb` 文件（`File` / `URL.createObjectURL`）预览，不保存绝对路径、不上传文件、不嵌入发布包；生产构建没有该加载入口。
- 任意外部模型缺席或加载失败，角色仍显示现有 SVG。构建后逐项检查 `dist/` 与 Windows 安装包不包含四个第三方模型文件或其贴图，同时检查生产 UI 没有本机加载入口。

## 设计判断与待验

- 先让伙伴页与浮层按需渲染三维；多处小缩略图和记录时光保留现有画像。这样避免同时建立多个 WebGL 上下文，属于本轮实现边界，而非用户已逐一指定。
- 必须有加载失败、WebGL 不可用时的现有画像回退；减少动态、休息、拖动和失焦时停止连续绘制。
- 五个角色的侧面、背面细节无法由现有单视图完整确认；灰模需要实际视觉验收。
- 需在 Web 和 Tauri Windows 实测模型打包、画布性能、交互和资源释放。

## 阶段与证据责任

1. 模型阶段：先产晴小团灰模及三视图，再产另外四个灰模；记录每个角色的 Blender 源、导出版本、可见外形差异和动作剪辑名。用户对造型的反馈决定是否细化。
2. 接入阶段：沿用 `PetPortrait` 调用边界，三维挂载只覆盖晴小团已确认的两个入口；缩略图/记录时光与第三方角色保留 SVG。每个入口核对轻触、休息、拖动、弹层、失焦和减少动态。模型加载失败、WebGL 不可用有可视回退。
3. 发布验证由根任务独立执行：`npm test`、`npm run build`、原生构建、实际 Web 与 Windows UI、制品资源扫描、切换/退出后的资源释放观察；失败和未测单列。公开包边界由根任务负责，不由建模素材名称推断。
4. 既有 `docs/current/pet-space-customization/` 是 SVG 装扮与旧空间工作，属于历史输入；新三维结果只记在本 feature。原工作区未提交改动不重置、不混作本轮提交。
