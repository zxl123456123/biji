# 记录查找体验

✅ 已实现于0.5.5。本轮解决主搜索与快速打开匹配口径不同，以及长记录只预览开头、看不到命中内容的问题。保留本地字面查找，不改变存储格式。

## 匹配与结果顺序

两入口共用同一个选择器，按现有有限格式解析后的可见正文，加一个空格，再连接原顺序的`#标签`进行查找。查询首尾去空白、按默认Unicode小写比较，仍是完整子串匹配；不做重音等价、NFKC、模糊匹配或相关性排名。粗体/斜体内部语法不参与匹配，代码中用户看到的格式符号和HTML样文字仍作为正文。

精确标签、未完成、回收站条件仍与主查询取交集；精确标签保持大小写区别。快开查完整活动源，不受主列表筛选或展示批次限制。匹配保留源数组顺序和记录引用，置顶投影由原展示层负责。本轮统一也保留快开既有正文/标签跨界短语，例如正文“收尾”与标签“旅行”可匹配“收尾 #旅行”。

## 结果辨识与操作

快开有查询时显示首个非空正文行、首个命中附近的摘要，以及明确标为“创建”的年月日与标签。摘要通常保留命中前16个字形和最多120个字形；完整命中长于窗口时保留该命中。裁剪处加省略号，摘要中的换行在界面压缩为空白，不改变实际查询语义。空查询继续展示开头两行，没有高亮。

高亮由React文本节点和`mark`组成，不注入HTML。默认Unicode小写可能将`İ`展开为两个字符，高亮先映射回原文；裁剪/高亮使用原生`Intl.Segmenter`完整字形边界，避免拆开代理对、组合字符与ZWJ emoji。查询命中字形的一部分时突出完整字形。

默认按40条分批，方向键越过批次会继续显示所选记录，首项ArrowUp环绕末项可一次显示至末项；40是默认批次而非最大显示量。Enter编辑，Ctrl/⌘ Enter在关联图定位，Esc关闭。动作使用UUID，重复正文不会合并。键盘、焦点交接和动态开关沿用已有实现。

## 查询成本与缓存

派生搜索串按记录对象用WeakMap缓存，同时检查content是否变化；正文修改或替换记录时重新解析，旧对象可回收。缓存只在内存，不修改SQLite/备份或添加索引。快开摘要按匹配源、查询及展示数量复用；在当前批次移动选中项不会重新生成40份摘要。默认小写命中通过原文前缀长度二分映射，使用原生Segments.containing直接定位邻近字形，最多向前16、向后120次访问，不逐字遍历长文前缀。

长正文的首次解析、字符串查找和小写映射仍有成本，加载更多也会增加展示成本；不能把热查询计时理解成界面帧率承诺。实际测量与未测边界见[0.5.5验证记录](Release.Verification.0.5.5.md)。

## 参考与取舍

参考[Joplin共享SearchEngine供搜索与GotoAnything](https://joplinapp.org/help/dev/spec/search_sorting/)的入口一致性，采用现有解析器和一个选择器；暂不引入BM25/FTS数据库索引，当前小范围需求不需要新增查询协议或迁移。参考[Obsidian搜索上下文](https://obsidian.md/help/Plugins/Search)帮助用户辨认命中记录的思路，仅加入轻量首命中摘要，不扩展高级搜索语法。字形边界使用[原生Intl.Segmenter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter)，没有新增Unicode依赖；旧浏览器兼容未纳入本轮声明。

⛔ 未实现：独立只读阅读窗、高级查询、相关性排序、全文索引。🕒 未来可能：在真实长文使用数据和浏览器性能分析支持后，再决定是否需要更细的摘要缓存或异步索引。
