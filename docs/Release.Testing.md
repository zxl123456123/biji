## 自动检查

```powershell
npm ci
npm test
npm run check
```

`npm run check` 会执行 TypeScript 构建、Vite 正式构建和 Rust 编译检查。开发预览使用 `npm run dev`，桌面联调使用 `npm run desktop`。

Rust 测试命令：

```powershell
cargo check --locked --manifest-path src-tauri/Cargo.toml --jobs 1 --tests
cargo test --locked --manifest-path src-tauri/Cargo.toml --jobs 1
```

✅ 0.5.4新增9项消费生产连接helper的数据库/serde用例；root独立运行上述check/test退出0，9/9、fail0。覆盖旧7/8列旧字段保持、新10列重复初始化、完整数组顺序/pin/回收站/非空交易、NULL位置回退、两种插入失败的两表回滚、旧JSON缺pin和实际临时文件关闭重开。`check --tests`仅编译；数据库运行证据来自`cargo test`，不等同于真实用户旧库、新EXE或完整平台验收。

截至0.5.3的历史版本无实际Rust业务用例。0.5.2主代理以`--locked --jobs 1`执行退出0；0.5.3不改Rust业务，未另跑Rust check/test，Windows正式构建编译退出0。“0个测试通过”不等同于迁移自动覆盖。0.5.0三次内存失败和0.5.1分页失败继续保留。

`npm test` 使用 Node.js 22.18+ 的内置测试与 TypeScript 类型擦除；0.5.4最后生命周期修正后root独立80/80、fail/skip/cancel均0及build exit0。保留原69项，新增9项排序槽位、pin字段/图语义、同组门禁、共同批次、备份和最终落点，加2项实际生产layout cleanup失效/stop次序与未绑定manager边界。它不代替真实sensor/焦点/编辑器或原生数据库验收，Web实际矩阵与纯测试分开记录；内存不足时可用 `node --test --test-concurrency=1 tests/*.test.mjs` 串行执行同一全量集合，不与构建并行。

0.5.1历史：主代理50项、build、jobs1 Rust check及Windows release退出0；该轮Rust test因os1455分页文件不足退出1。0.5.2最终新全量69项、Web构建、Rust check/test及Windows release退出0，保留Node ExperimentalWarning与Rust linker_messages warning。r2候选失效/r3 E0460 exit1→定向缓存处理后r4新包证据分别保留；该版Rust仍0业务用例，不覆盖0.5.4该版的9项新增测试。

## 里程碑人工验收

1. 新建记录，输入内容后直接关闭，再次新建时应恢复草稿。
2. 保存草稿后再次新建，旧草稿不应继续出现。
3. 删除记录后点击“撤销”，记录应回到原列表。
4. 不撤销时记录应进入回收站，点击恢复后回到原日期。
5. 永久删除第一次点击只显示风险提示，必须再次确认才删除。
6. 旧版 SQLite 数据库打开后，原有笔记和账目仍然存在。
7. 浅色、深色以及 Windows 100%、125%、150% 缩放下检查弹窗和按钮。

8. 连续输入、选区标题/粗斜体/列表、保存展示、编辑回填、快捷保存与查找。
9. 精确标签与近似名、未完成/文本组合、清除反馈；复制正文与复制失败提示。
10. 本月图表/流水不包括跨月账目；账本新建入口直接记账。
11. 宽/窄、浅/深、触屏动作、Tab/Shift+Tab 留在弹窗、关闭焦点恢复。
12. 光粒开关、系统减弱、后台恢复与连续输入并行，记录实际性能/包体和未测项。
